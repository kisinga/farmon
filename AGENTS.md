## Local tier architecture

The local tier is complete on its own; the cloud adds only remote reach, alerts, history and multi-site.

- **`local` topology field** — per-controller options (`buttons`, `ui`, `rtc`) on `Controller.local`, schema 19, `src/lib/topology.types.ts`.
- **Panel buttons** — `src/lib/codegen/generators/local-inputs.ts` maps board digital inputs (KC868-A16 IN1–IN16) to actions: IN1 is always Stop All, each later input toggles one route. Auto-assigned by default; an explicit `local.buttons` overrides.
- **Automation persistence** — `firmware/components/maji_automations` saves the last-good set to NVS on every apply and restores it at boot through the same validation path; schedules survive reboots and power cuts with no server.
- **On-device dashboard** (`local.ui`) — the `maji_local_ui` component replaces the stock ESPHome web_server page and serves the operator dashboard from flash: `GET /`, `GET /local/state` (SSE), `GET /local/automations` (wire blob), `POST /local/command`, `POST /local/automations`. The device-mode app is built ONCE with `npm run build:device` (no site-config argument — nothing is baked per site): `dist/device/browser` holds every asset pre-gzipped (`<name>.gz`) plus `device-ui-manifest.json` (`{ version: 1, assets: [{ path, file, contentType, immutable }] }`). The server hosts that directory raw at `/device-ui/` (`MAJI_DEVICE_UI_DIR`, baked to `/app/device-ui` in the image — no `Content-Encoding`, the browser gunzips); the codegen fetches the manifest + assets from there at bundle-generation time and embeds them into `local-ui-assets.h`. The site topology rides the firmware the same way: the device serves `/topology.json`, which the app fetches at runtime (`src/app/device/device-topology.ts`) — so one build serves every site. App bundle uses hash-location + index fallback for SPA routes. SSE slots are released only via the httpd `free_ctx` destroy callback — never recycle a slot from the stall path. Automations edit on-device works end-to-end: `DeviceAutomationsService` (swap in `device.providers.ts`) list/mutate via `GET`/`POST /local/automations` (decoder in `src/lib/automation-wire.ts`); names live in localStorage. The Activity feed renders on-device too: the snapshot carries an `events[]` ring (newest-first, max 10 — `SnapshotEvent` in `src/lib/codegen-ids.ts`), surfaced by `DeviceRealtimeService.recentDeviceEvents`/`subscribeDeviceEvents` and mapped to the shared activity rows in `src/app/device/device-activity.ts`. Commands from this app tag `actor: 'local-ui'` in the envelope; panel buttons tag `panel`. Both are reserved actor ids (`RESERVED_ACTOR_LABELS`) — the server labels them at ingest ("Panel button" / "On-device dashboard"), the on-device feed from the same map.
- **RTC** (`local.rtc`) — optional DS3231 on the board I2C bus (0x68) so time-based schedules run fully offline. Default is SNTP-only; time is trusted after a valid RTC boot read or a real SNTP sync (`src/lib/codegen/generators/time-sync.ts`).

## Tenant billing + Shengda meters

Cloud-only module (migrations 57–59; spec `docs/billing-shengda-implementation-spec.md`, domain model `docs/billing-module-architecture.md`). Battery-powered Shengda ultrasonic meters (NB-IoT/Cat.1, built-in valve) report cumulative readings over raw UDP — no field controller, no MQTT, no auth at the wire layer (accepted risk; mitigation: only claimed meters feed billing, valve commands echo the device-reported IMEI, new-source-IP events).

- **Codec** — `maji-server/internal/metering` (frame parse/build, CBOR objects). CRC16 is AUG-CCITT (SPI-FUJITSU), big-endian, full frame minus CRC — locked by fixture tests; the vendor PDF's time-calib hex has a one-byte typo (extra `62`), corrected in the spec. Reading dedupe key is `(meter, message_id, device_ts)` — the wire's message ID is a random 16-bit value and collides on its own. Readings store integer **millilitres** (wire reports litres; convert at ingest).
- **Sessions** — meters sleep; downlink is possible only in the ~20s window after an uplink: reply time-calib immediately (SN must echo), flush ONE queued command, match its ack (FuncCmdResult) by IMEI. `meter_commands` is the persistent queue: queued → sent → acked | expired (48h TTL sweeper).
- **Billing spine** — `maji-server/internal/billing`: scheduler (create_cycle → prepare_invoices from boundary readings × tariff → daily mark_overdue), manual payments allocated oldest-debt-first, arrears automation (overdue > grace_days → warn → > warn_days → `valve_close`; settled → `valve_open`; `rule:arrears` actor id; never closes unwarned; idempotent via `warned_at`/`closed_at` + pending-valve guard). Money is integer minor units everywhere.
- **Gating, two layers** — global `billing_module` feature flag (UI routes) + per-site `tenant_billing` capability (`sites.addons` ∪ `packs.capabilities`, `billing.HasCapability` on every route/job). Entitlement fields are admin-only writes (`guardEntitlement*` in `sites_hooks.go`).
- **Listener** — starts only on the cloud binary when `MAJI_METER_UDP_ADDR` is set. Dashboard: `site/:name/billing/*` (Angular), valve actions need typed confirmation; queued commands always show "pending — applies at next meter contact (up to 24h)".
